# v0.7.29：剧情助手与 Agent 接口

## 先看这里

本版增加了把小说、大纲编排成可试玩粗稿的工作流程。AI 编排使用你连接的 Agent；编辑器本身没有内置模型，也没有捆绑 AI 账号或密钥。

顶部点击 **剧情助手** 即可打开。原有编辑器和游戏界面风格保留。

## 作者怎么使用

1. 新建或打开工程。
2. 点击“剧情助手”，导入 TXT、Markdown 或 Word（DOCX），也可以直接粘贴小说或大纲。支持分次导入多个章节，工程中可保存最多 200 万字故事素材。
3. 选择“忠实原文”“游戏化改编”或“根据大纲扩写”，填写自己的编排要求，点击保存编排要求。
4. 批量导入 VRM、图片、VRMA/FBX、音乐音效或视频。素材会自动归类到“剧情助手导入”文件夹。填写标签，例如“港口、白天、紧张、挥手”，再保存标签。
5. 点击“开启本地 Agent 接口”，复制 MCP 配置，添加到支持 MCP 的 Agent。配置中的连接编号只对应当前窗口；关闭、断开或重开接口后需要更新配置。
6. 点击“复制编排任务”，粘贴给已连接的 Agent。它可以按章节读取文本，导入作者指定的素材，编排角色、幕、对白、动作、表情、背景、音乐、天气和新闻事件。
7. Agent 提交后，粗稿显示在助手右侧。可以让 Agent 采用，也可以自己点“采用粗稿”。采用会追加到剧情末尾，原有剧情和角色介绍保留；新建工程的默认示例对白会被粗稿替换。
8. 点击试玩检查，继续手动调整，再保存或导出。

缺模型或背景时，仍能创建对白和粗稿，右侧会列出待完善事项。Agent 如果引用了不存在的素材编号，编辑器会拒绝这一批粗稿并说明原因。

## 没有连接 Agent 时

- “快速拆分（不使用 AI）”：识别章节标题和“角色：对白”，普通小说段落暂时保留为旁白。它不理解剧情，不会自动挑选音乐或动作。
- “导入粗稿 JSON”：让其他 AI 按附带的粗稿格式生成文件，再导入、预览、采用。
- 本版不生成 VRM、背景图或配音，也不提供音频内容识别。Agent 依据素材名称、标签和作者说明进行安排。
- 配音继续遵守原有规则：必须在对应角色的对白上传，素材库中按全文命名，存入不可删除的角色专属文件夹。

## 粗稿采用与撤销

- 一批粗稿作为一次修改，可整批撤销、重做。
- 已存在的角色按完整名称复用，已有介绍和模型绑定不会被粗稿覆盖。重名角色需要先区分。
- 超过三位说话人物的场景会拆成连续小幕，避免第四位人物的模型无法上场。
- 默认保留每幕根据背景自动调整的功能。
- 若作者在粗稿预览后修改了工程，需要重新提交粗稿检查；旧预览不能直接覆盖新修改。
- 同一份粗稿不能重复采用。
- 作者上传的小说和编排要求保存在加密工程中，导出的玩家游戏不包含这些作者工作资料。

## MCP 和 CLI

完整安装包新增 `VRMGalgame.Agent.exe`。不需要另外安装 Node.js、Python 或 .NET。

MCP 使用本地 stdio，操作当前编辑器窗口；本地连接仅限当前 Windows 用户。关闭编辑器或点“断开 Agent”即停止接入。它不直接修改磁盘上的旧工程内容，能够读到未保存的修改。

提供 14 个工具：

| 工具 | 用途 |
|---|---|
| list_sessions | 列出已开启接口的编辑器窗口 |
| get_project | 当前工程、角色、素材、编排要求和文本目录 |
| get_act | 读取指定幕的完整对白和设置 |
| get_source | 按章节、分段读取故事文本 |
| read_document | 导入作者指定的 TXT、MD、DOCX |
| import_assets | 复制作者指定的素材并归类 |
| set_asset_tags | 设置素材说明标签 |
| propose_draft | 检查粗稿并展示预览 |
| apply_draft | 采用已检查的粗稿 |
| undo / redo | 撤销和重做 |
| save | 使用现有加密格式保存 |
| preview | 打开当前工程的可试玩预览 |
| export_game | 导出到一个新的文件夹 |

命令行示例，在安装包目录打开终端后运行：

```powershell
.\VRMGalgame.Agent.exe --list-sessions
.\VRMGalgame.Agent.exe --call get_project
.\VRMGalgame.Agent.exe --call propose_draft --input arguments.json
```

多个编辑器开启接口时，请加 `--session 连接编号`。写入操作需要提供刚读取到的 `expectedRevision`，用于防止作者和 Agent 的修改互相覆盖。

粗稿格式示例见 `Agent粗稿格式示例.json`。CLI 的 `propose_draft` 参数是 `{ "expectedRevision": 当前编号, "draft": 粗稿对象 }`；导入 JSON 按钮直接读取粗稿对象。

## 已检查的范围

通过实际 Windows 编辑器验证了文本导入、Word 正文与旧编码中文 TXT、分段读取、真实素材导入、标签、粗稿检查与采用、原剧情保留、撤销重做、重复与过期请求拒绝、MCP stdio、CLI、加密保存、游戏导出。

自动改编的质量取决于所连接的 Agent、作者要求和素材说明。本版的接口检查保证工程结构可用；故事节奏和艺术效果仍需要作者试玩检查。
