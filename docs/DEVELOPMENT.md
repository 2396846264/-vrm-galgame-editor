# 开发与维护规范

适用于当前 JavaScript / Vite 前端、Windows 桌面宿主和 Agent。所有开发者与 Agent 修改前必须先阅读源码根目录的 [代码开发规范](../代码开发规范.md)，再按本文件查找模块职责和验证入口；作者署名和来源要求继续按根目录 AGENTS.md 执行。

## 模块职责

| 目录 | 职责 | 依赖限制 |
| --- | --- | --- |
| `src/platform` | WebView 通信、资源 URL 等平台适配 | 不依赖编辑器面板或工程业务 |
| `src/project` | 工程数据默认值与旧数据迁移 | 不持有编辑会话、播放器或 DOM 状态 |
| `src/player` | 玩家存档等运行期服务 | 不写作者的编辑选择或撤销历史 |
| `src/player/progress.js` | 已读与鉴赏进度、旧进度迁移、统计 | 只接收工程/模式读取与存储接口，不操作 DOM；缓存兼容接口仅用于现有测试接线 |
| `src/player/media-preloader.js` | 预加载媒体及其释放 | 音频取出后交给播放方管理；失效任务释放自己创建的资源 |
| `src/editor/panels` | 属性面板与控件的只读内容生成 | 接收展示数据和具体辅助函数；不提交工程修改、不创建舞台、不注册监听器 |
| `src/editor/preferences.js` | 本机编辑器偏好读写 | 保留存储键和旧外观版本规则；不导入样式或注册自动保存任务 |
| `src/editor/commands` | 幕、对白、角色、附件、素材与物品的数据修改 | 不读 DOM、不发送宿主消息、不注册历史事务；调用方先确认操作和选择，再按原顺序提交历史、刷新界面 |
| `src/editor/history-input.js` | 输入和拖动的撤销分组 | 在捕获阶段记录修改前状态；只持有手势分组状态，关闭页面时移除监听器 |
| `src/editor/session.js` | 修改标记、修订号和统一历史提交 | 工程迁移、配音与素材整理先于修订号及历史提交；不保存界面选择，不直接操作 DOM |
| `src/editor/module-session.js` | 子窗口基线、历史重基和通知队列 | 保存期间暂存刷新，保持旧修订过滤与三方合并；界面仍负责按 ID 恢复选择和输入焦点 |
| `src/editor/persistence.js` | 保存快照、请求状态、修订号与待删除头像筛选 | 保存期间的新编辑不能被标为已保存；子窗口合并和界面更新通过明确的回调接回控制器 |
| `src/editor/portrait-assets.js` | 自动头像的引用整理和待删除路径 | 撤销仍引用的文件由保存流程继续保留；共享物理文件不能误删 |
| `src/editor/portrait-jobs.js` | 头像生成任务、失效结果检查和试玩临时头像 | 保留手动头像、历史修正与重复任务规则；不持有舞台或操作 DOM |
| `src/ui/markup.js` | 通用控件、转义和编辑器标签 | 不读取工程或持有会话状态 |
| `src/events` | 事件的数据定义 | 数据定义不导入事件界面或运行器 |
| `src/rendering` | 头像捕获、动作切片和动作转换 | 不反向导入 `renderer.js` 或应用入口 |
| `src/combat` | 武器、单位控制、损伤呈现等战斗子系统 | 由运行协调器传入战斗状态，更新顺序由协调器决定 |
| `src/agent` | 工具字段定义、通用校验与领域校验 | 与界面共享业务规则，不导入界面入口 |
| `src/testing` | 旧回归场景及测试适配器 | 生产业务不能依赖测试场景；普通启动按需加载 |
| `Desktop/Projects` | 工程归档和工程文件筛选 | 不访问窗口、WebView 或当前界面选择 |
| `Desktop/Testing` | 原生回归编排 | 通过显式测试接口调用宿主，不作为业务服务 |

根目录已有功能文件是渐进迁移中的兼容入口。导出名称和调用方尚未全部迁移前可以保留薄封装，但不能把新业务继续堆入入口。

## 状态与修改

工程数据、编辑会话、玩家运行、本机偏好、临时资源分别维护。模型、材质、计时器、音频实例不能进入工程序列化或玩家存档。

所有新的工程编辑操作先进入所属领域的命令，再完成校验、原子提交、撤销记录、修订号和跨窗口通知。按钮、快捷键和 Agent 应调用同一个业务命令。迁移旧操作时必须保留当前保存并发、三方合并和撤销语义。

旧路径中，工具栏与右键删除幕、界面与 Agent 创建/删除对象存在默认值及引用处理差异。本轮只迁移现有界面命令，不顺带统一这些差异。命令的索引和前置条件由当前控制器保证；迁移 Agent 前必须明确兼容契约并分别验证，不能直接替换后宣称等价。

禁止新增万能 `AppContext` 或向每个模块传入整个应用状态。测试适配器允许显式访问旧状态以保留回归场景；不得将其复制为生产架构。高频动画和物理更新使用所属运行模块的数据，不逐帧复制整个工程或广播所有内部变化。

## 依赖与生命周期

模块不能导入 `main.js`，不能通过全局变量读取另一模块的私有状态。应用层负责组合模块；数据模块不应依赖 DOM、窗口、资源加载器或具体渲染器。新模块应有清楚的公开接口，避免创建万能工具或管理器文件。

创建监听器、定时器、音频、对象 URL、材质、几何体和渲染器的模块负责释放。异步加载必须能识别失效请求，切换工程、切幕或关闭窗口后，旧结果不能写入新会话。共享缓存需明确所有者，不能在拆分时变成多个重复缓存。

保持角色更新中的动画、动作摆放、脚锁、物理、视线、附件和头像的既有顺序。战斗协调器继续统一决定模拟更新与呈现顺序；拆分子系统不代表允许独立改变时间步长。

## 规模与格式

- 启动入口以约 200 行为目标，只做初始化和组装。
- 普通业务模块超过 400 行需要评审；超过 800 行或 40 KiB 需要拆分职责或明确的例外理由。
- 普通函数超过 60 行需要评审，超过 100 行重点检查其职责与依赖。
- 不允许压缩大量语句到单行来规避规模检查。新增模块使用已配置的格式工具。
- 历史大文件登记在 `scripts/architecture-baseline.json`，现阶段限制增长，逐步降低预算。禁止为了通过检查而直接提高预算。
- 不再新增 `EditorWindow` 的 partial 文件；独立业务应成为独立服务。已有 partial 类仍是后续迁移对象。
- 翻译数据、着色器、第三方源码和旧测试场景按各自性质维护，不能与业务代码混算。

新目录使用功能名称。版本号只用于发行记录、迁移记录和确实需要区分历史格式的实现，不作为新增业务模块的常规名称。

## 数据兼容

结构重构默认不改变工程、玩家存档、通信协议或发行版本。需要改变格式时，单独说明数据版本、默认值、迁移规则、资源引用、导出行为和回退方式。

保留工程与资源 ID、存档关联及已有默认行为。工程归档加密与发行签名分别维护，不能因为更换电脑或构建资料变化而改变旧工程读取约定。兼容测试使用原工程副本，不能覆盖用户原工程。

## 开发检查入口

```text
npm run check:architecture   # 语法、相对导入、静态循环、规模预算和窗口类增长
npm test                    # 与 CI 相同的普通源码回归
npm run test:fixtures -- --fixtures <JSON文件>  # 还包括需要额外素材的三项检查
npm run format:check        # 已迁移模块的格式检查
npm run format:modules      # 格式化已迁移模块
npm run build              # 前端构建及 PDF 资源复制
```

外部素材回归的排除清单由 `scripts/run-tests.mjs` 统一管理，并在输出中明确列出。普通源码回归不能因为没有提供模型文件而偷偷跳过其他检查。

素材配置 JSON 将脚本名称映射到该脚本的参数数组：`test-anon-secondary.mjs` 需要爱音 PMX 文件，`test-white-motion72.mjs` 与 `test-white73.mjs` 需要含 `.mixamo.fbx` 的目录。前者还依赖现有 `work/v030-environment-fixture/assets/motion/移动_女性走路.fbx`。也可以通过 `VRMGALGAME_TEST_FIXTURES` 指定配置文件。私人素材路径保存在本机配置中，不提交源码；缺少配置时入口明确报错，不会伪装为测试通过。

归档服务的独立检查入口是 `scripts/project-archive-checks/ProjectArchiveChecks.csproj`：首个参数为测试输出目录，其余参数为旧 `.vrmg` 工程路径。它在副本上执行加密读写、资源筛选、失败保存保护、连续保存和重开，输出中不得包含密码。

浏览器和原生回归用于验证用户操作、画面和宿主集成；单纯构建成功或纯数据测试成功不能替代这些验证。检查动作草稿时，先验证取消不提交，再验证点击应用后的结果。维护测试应更新过时的操作步骤，不能改变预期业务行为来迁就重构。

`scripts/test-main-services.mjs` 覆盖偏好兼容、旧进度迁移、工程存储隔离、已编辑对白的进度规则及媒体资源所有权。`scripts/test-main-modules-browser.cjs <输出目录> [拆分前基线JSON]` 检查八种面板状态、偏好和进度；提供基线时逐项比较。浏览器脚本使用本机 Playwright（可通过 `PLAYWRIGHT_MODULE` 指定），不会改变实际工程文件。

`scripts/test-editor-services.mjs` 验证编辑命令、撤销资源保留、保存失败、重叠保存和输入分组；`scripts/test-editor-portraits.mjs` 验证头像任务去重、过期捕获/保存、手动头像、历史修正和共享文件。`scripts/test-editor-commands-browser.cjs <输出目录> [基线JSON]` 通过真实点击、输入与撤销重做比较 22 个状态；工程内容计算完整 SHA-256，避免把内置素材重复写入每个快照。

`scripts/test-editor-session.mjs` 覆盖会话提交顺序、派生历史、通知去抖、保存期间排队的最后一条刷新、独立编辑合并、冲突保留原状态及历史重基。测试适配器保留原 `dirty`、`changeRevision` 和 `moduleBaseline` 属性名，通过显式接线访问所属服务；生产模块不可依赖这些测试接口。

## 每次变更的完成条件

记录问题、所属模块、数据或协议变化、验证方式和回退方式。按功能范围核对编辑、预览、运行、撤销重做、保存重开、导出、Agent 和多窗口路径；不适用的项目写明原因。

结构调整与行为修改分批记录。先建立可回退基线，每迁移一个职责就完成相关回归。发布前应补齐代表性旧工程副本的打开、保存、重开，以及涉及的原生窗口和导出游戏检查。

## 仍需逐步迁移的部分

面板内容、常用编辑命令、输入历史分组、修改状态、保存请求协调、子窗口基线同步、头像资源与生成任务已从 `main.js` 迁出。`main.js` 仍负责编辑选择、命令前置确认、输入分发、历史恢复界面、主窗口接收子窗口提交后的保存编排与玩家播放；这些界面与运行控制尚未全部拆分。载具、环境与火力页面仍需分离页面会话和输入控制；`EditorWindow` 仍有历史 partial 服务与测试方法。不能因为入口文件变短就宣称这些耦合已经全部消除。

后续迁移优先从已有测试覆盖的领域命令和会话状态入手，再分离编辑器与玩家启动组合。样式作用域、跨窗口消息契约以及更深层的模型加载与战斗状态拆分应独立验证。
